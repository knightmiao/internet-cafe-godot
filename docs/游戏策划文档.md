# 网吧模拟经营游戏 —— 游戏策划文档 v0.1

> 依据《网吧-模拟经营游戏制作-会议记录.txt》整理扩展
> 核心玩法：以「钱」为核心的网吧模拟经营，05年怀旧时代背景

---

## 一、游戏概述

### 1.1 核心卖点
- **财务驱动**：一切围绕「收入」与「支出」，两者均含效率逻辑，商业变现直接摆在首位
- **怀旧时代感**：设定在 2005 年，深度还原中国互联网起步期的网吧生态
- **随机事件博弈**：历史事件 / 热门游戏 / 特殊客人触发，用选择制造经营风险与乐趣
- **成长线**：从小网吧一步步装修、扩员、升级，做大做强

### 1.2 玩家身份
主角厌倦大城市互联网生活，辞职回老家，继承去世叔叔留下的**神秘小网吧**，为重温童年快乐而将网吧做大做强。

**形象设定（美术基准）**

| 角色 | 设定 |
|------|------|
| 老板（主角） | 年轻男生，身形偏瘦、窄肩；圆框眼镜；韩式蓬松卷发，深棕色；青蓝色衬衫 + 米色围裙 |
| 布偶猫「店长」 | 海豹双色（Seal Bicolor）布偶猫。白身白爪，耳朵与眼周为深海豹棕面罩，两眼之间一道白 blaze，蓝色杏仁眼，深色粗尾。常驻收银台面 |

形象基准图见 `docs/ui/concept/`，右栏柜台特写素材由此产出。

### 1.3 目标
从一家破旧小网吧起步，通过每日经营积累资金，逐步扩张为大型网咖，乃至电竞酒店连锁。

## 二、游戏循环（每日经营流程）

玩家作为老板，每日需执行一系列操作维持运营：

1. **开店准备**：点击开店后自动启动所有正常且清洁的机器；玩家无需逐台重复开机
2. **环境维护**：安排清洁工打扫，维持大厅清洁度与顾客心情
3. **员工调度**：店员按时到岗、接待顾客刷身份证、核对区域上机人数与座位匹配度
4. **供应链采购**：联系供应商采购食材与小食品，保障小吃供应充足
5. **经营收尾**：结算当日收支、查看报表、处理随机事件、规划次日

（时间尺度：暂定以「一天」为单位，后续可调整为「一周」）

**操作原则**：采用半自动经营。正常机器启停和重复性流程尽量自动化，玩家集中处理故障、脏污、顾客需求以及价格、采购、排班、升级等经营决策。高频动作一键执行，复杂动作打开小面板。详见 `docs/ui/操作区功能规划.md`。

## 三、核心系统模块（三大支柱）

### 3.1 财务管理模块 ⭐（核心优先级最高）
> 会议明确：优先跑通财务系统，先把「钱」算明白

**收入来源**
- 网费收入（按机器、按时段、按区域计费）
- 增值性服务收入（小卖部小吃、包间差价、会员充值）

**支出构成**
- 人力成本（工资、奖金）
- 水电房租（固定 + 浮动）
- 机器升级折旧
- 软件服务费
- 带宽费
- 周边进货成本

**核心逻辑**：收支平衡 + 利润率 + 现金流管理，玩家决策直接影响财务健康度

### 3.2 人力管理模块
- **时间安排**：店员排班（到岗时间、时段覆盖）
- **调班 / 招聘 / 解聘**
- **福利 / 奖金发放**
- 员工状态影响服务效率与顾客满意度

### 3.3 机器管理模块
- **网吧包间布局**：大厅 vs 包间的差异化定价
- **环境设置**：清洁度、装修档次、氛围
- **机器性能配置**：硬件等级影响可运行游戏与收费标准
- **热门游戏资源管理**：游戏库管理，爆款游戏拉动客流

## 四、经营流程（从外到内结构）

```
营销广告 → 店铺装修 → 会员阶梯 → 价格与包间选择
        → 机器配置 → 配套小卖部 → 未来电竞酒店连锁
```

## 五、阶段发展 / 成长线

店面体量按县城常规网吧调研落地（证照齐全、普通规模）：低于 40 台难回本，标准店 70～90 台，包间机位不超过总台数 30%。

- **初期（当前）**：继承破旧小店，**40 台**，约等于县城「偏小门店」下限。大厅为主、包间克制，无高配区 / 战队房 / 无烟区。
- **成长期**：扩到 **60～80 台**（县城最常见体量）。装修高配大厅、再开 1～2 间四人开黑房，硬件升级。
- **扩张期**：冲 **100 台上下**。加战队大包、无烟区、会员与小卖部深化；再往上才是电竞馆 / 电竞酒店连锁。
- **愿景**：电竞酒店连锁化

详见 `docs/ui/初期店面规划.md`。

## 六、随机事件系统（趣味性核心）⭐

> 设定背景 05 年，随玩家天数增长，每隔一段时间触发模仿中国网络发展历史的随机事件

### 6.1 历史事件类型
- **热门游戏发布**：如 CS:GO 发布、梦幻西游火爆、DNF 畅销 → 当晚客流量暴涨
- **网络文化普及**：火星文流行等时代特征事件 → 改变顾客群体特征
- **特殊客人事件**：如有人连续上网超 24 小时引发健康危机或砸店风险

### 6.2 特殊客人抉择机制
- 玩家需在「**劝离**」与「**升级为黄金用户打折**」间做选择
- 结果具有**概率性**，影响客流与声誉
- 设计目的：把经营风险转化为博弈乐趣，提升策略深度

## 七、模块优先级建议（MVP 落地顺序）

| 优先级 | 模块 | 理由 |
|--------|------|------|
| P0 | 财务管理系统 | 会议明确最先跑通，核心指标「钱」 |
| P0 | 基础每日经营循环 | 开机/接待/清洁/采购，让游戏转起来 |
| P1 | 机器管理 | 定价、布局、配置的承载体 |
| P1 | 人力管理 | 员工是经营的必要成本与资源 |
| P2 | 随机事件系统 | 趣味性加分项，MVP 后期加入 |
| P2 | 成长线/阶段 | 纵深感，后续扩展 |

## 七·五、顶栏（TopBar）UI 元素设计

> topbar 是全局核心信息的常驻展示区，信息密度需克制（6~8 项为舒适区），按「必选 / 建议 / 可选」分层，左右两侧排布。

### 7.5.1 元素清单

**左侧：品牌区**
| 元素 | 内容 | 说明 |
|------|------|------|
| 🏷 品牌 Logo + 文案 | 猫网电竞 | 常驻，金色发光描边 |

**中部：经营核心指标**
| 元素 | 内容 | 说明 |
|------|------|------|
| 📅 天数 · 时段 | 「第3天 · 午后」/ 具体时间 | 天数与时段合并为一项，时段影响客流量 |
| 💰 金钱 | 当前现金 | 负值变红，支持千分位与飘字动画 |
| 🖥 在线 / 总机台 | 「12 / 20 台」 | 一眼看生意热度，网吧辨识度核心 |
| 👥 客户数量 | 当前在店人数 | |
| ⭐ 声誉 | 声誉值 / 星级 | |
| 🧹 清洁度 | 0~100 | |
| 🛋 装修值 | 0~100 | |

**右侧：交互入口**
| 元素 | 内容 | 说明 |
|------|------|------|
| 🔔 消息铃 | 事件红点徽标 | 有事件时亮红点 + 抖动动画 |

| 元素 | 图标方案 | 推荐实现 |
|------|----------|----------|
| 品牌 | 网吧门头/显示器的吉祥物式简笔 | 自绘 PNG（TextureRect） |
| 天数·时段 | 🗓 日历 / ☀︎-🌙 时段 | Emoji 或自绘 SVG |
| 金钱 | 💰 金币 | Emoji/图标字体 |
| 在线机台 | 🖥️ 显示器 | Emoji/自绘 |
| 客户数量 | 👥 双人剪影 | Emoji/图标字体 |
| 声誉 | ⭐ 星级星星 | Emoji/自绘单色星 |
| 清洁度 | 🧹 扫帚 / 🧽 抹布 | Emoji/自绘 |
| 装修值 | 🛋️ 沙发 / 🎨 调色盘 | Emoji/自绘 |
| 消息铃 | 🔔 | Emoji/自绘，带红色 Badge 角标 |
| 设置 | ⚙ | Emoji/自绘齿轮 |

> 方案统一视觉风格：优先**同一套单色系线稿图标**（白描边，可随 Theme 变色），Emoji 仅作 MVP 占位快速验证，后期统一替换为自绘素材。

### 7.5.3 Godot 实现维度（对比 HTML）

- **数据绑定**：各指标用 GameManager 的 signal 连接，数值变化自动刷新 UI，非静态写死
- **状态联动**：资金不足时金钱标红 + 抖动；声誉跌破阈值变色告警
- **交互态**：按钮 hover/pressed/disabled 五态；消息铃红点徽标 + 抖动
- **视觉特效**：StyleBoxFlat 圆角阴影发光；Label BBCode 做金色描边 + 光晕；数值飘字 / 颜色过渡动画（Tween）
- **自适应**：HBoxContainer + size flags，窗口缩放时 spacer 吸收宽度，不挤压核心指标

## 九、单日经营闭环（已实现）

首版把演示壳换成可连续经营的一天，验收标准是不靠调试按钮连营 3 天，客流、余额、机位状态和日结能正确延续。数值按**三四线县城 / 地级市网吧**（约 2018–2024）压缩进游戏日，不按一线电竞馆定价。

**物价锚点**

- 计时网费：普通机 3～5 元/小时，电竞机 6～10 元/小时。六代时价 `3/4/5/6/8/10`，本轮不改。
- 包夜：一口价，不是 `时长 × 时价`。九系起 26 / 30 / 34 / 40 / 48 / 58 元，坐到打烊；强制收尾仍收一口价。
- 电费：商业用电 0.85 元/度。机位按 `power_watts`（开机才计）+ 店面基础 2000W + 已装空调各 800W，按分钟累加，关店入账。
- 小修：清灰、换键鼠维持 50 元。
- 客流：上午很闲（间隔 20 分钟），下午 10，晚上 5。不是三个时段差不多密。
- 脏污 / 故障：下机 22% / 4%；清洁低于 40 时脏污再 +8%。不是每场人都要拖地。
- 开局周转金 800 元，能买一台壁挂空调（180）并扛一两天电费；当天买不起红黑主题（520）。装修标价仍是游戏压缩价，本轮不重做价表。

**已闭环**

- 压缩实时时钟：营业日 480 游戏分钟，1× 下 1 秒 = 1 游戏分钟；走带键暂停 / 1× / 2×。
- 声誉为存档值，开局 3.5；展示 = `clamp(声誉 + 装修声誉 × 0.05, 1, 5)`。下机满意 +0.03、普通 0、不满 -0.05。客流间隔再除以 `展示声誉 / 3.5`，下限 4 分钟。
- 清洁 = `clamp(42 + 装修清洁 - 脏污×3 - 故障×2, 0, 100)`。舒适只改续坐：时长 `× (1 + 舒适 × 0.01)`，不改单价。
- 客流：仅营业中从 50 人角色库加权生成（匹配时段权重 3，否则 1；周末各时段权重 1）。柜台前排队上限 6 人；空闲机等待约 15 分钟后自动分配。白天→上午，午后→下午，晚间/夜间/深夜→晚上。
- 选座：安静座位优先包间；高配优先 `performance_score`；连坐优先旁边已有人的空位。
- 普通客：会话夹在 40～180 分钟，账单 = 时价 × 实际上机小时，四舍五入到元，**没有游戏化打折**。
- 心情三态（基准 50）：分区匹配 +15 / 错配 -10，时段匹配 +10，舒适与清洁加减，要高配却分到低分机 -10，排队每分钟 -1（最多 -20）。≥70 满意（时长再 +10%），<40 不满（时长 -20%，提前走）。心情只改待多久和口碑。
- 下机脏污故障保留到次日开店检查。清洁免费，维修固定扣 50 元。
- 电费按分钟累加，关店记支出科目「电费」。关掉空闲机省钱，装壁挂/立柜空调费电。
- 等级 `clamp(1 + (天数-1)/2, 1, 6)`，开局 1 级。
- 财务：收入和支出写入流水，今日营收与今日电费读真实账；装修购买、维修、电费走同一本账。
- 日结：停止接客后强制结算进行中会话，顾客清空后关店，汇总营收/电费/人数/脏污故障，天数 +1 并自动存档。
- 音效：Autoload `Sfx` 按 `godot/data/sfx_catalog.json` 播短音，设置「音效」滑条打 SFX 总线。UI 提示音与开店/上机/结账等店内纯音效分开；**音乐未做**。

**本轮未做**

员工自动接待与工资、小卖部、会员折扣、房租、广告营销、餐饮出餐、玩家自定义定价、BGM。这些入口仍保留在八模块里，数据标「待接入」。

调参见 `godot/data/sim_tuning.json`，包夜一口价见 `godot/data/pc_configs.json`，内核是 Autoload `GameState`。
