# 猫网电竞 · 素材生图管线

记录场景素材是怎么来的，以及重新生成时该怎么做。

## 一、为什么要有这条管线

早期核心场景的素材是用 Pillow 的 `ImageDraw` 逐个矩形硬编码画出来的，
结果就是"框线图"：明暗只有两三层，没有材质，物件像线框示意。
而右栏柜台立绘走的是另一条路——生图模型画概念稿，再降采样成像素画，
质感、光影、色彩层次全部来自原画，观感明显好得多。

差距用数据说话：

| 素材 | 尺寸 | 不透明像素 | 色数 |
|---|---|---|---|
| 柜台立绘（生图像素化） | 144×96 | 13824 | 40 |
| 旧机位（代码硬编码） | 24×28 | 446 | 16 |
| 旧顾客（代码硬编码） | 16×24 | 207 | 8 |

所以场景素材统一改走生图管线。但有个硬约束：**小尺寸 sprite 撑不住降采样**。
24×28 只有 446 个像素，生图降下来会糊成一团色块。因此场景像素密度整体放大到
原来的两倍（机位从 24×28 到一个座位 64×68），管线才成立。

## 二、两条管线的分工

| 管线 | 覆盖素材 | 脚本 |
|---|---|---|
| 生图 → 像素化 | 家具、设施、装修件、角色 | `import_stage_concepts.py` |
| 代码逐像素生成 | 地板、墙体、状态点、气泡、选中框 | `gen_stage_tiles.py` |

地板墙体必须无缝平铺，生图给不出可对接的边缘；状态点和气泡是功能反馈，
颜色要精确可控，不能被概念稿的光影带跑。这两类留在代码里。

## 三、生图约定

概念稿存放在 `docs/ui/concept/`，索引化为 256 色 PNG 后入库，
体积能压掉六成以上（本批 13 MB → 5 MB）。

> 注意：索引化对肉眼是无损的，但会改变下游像素化的结果——同一张稿压缩前后
> 跑 `gen_counter_portrait.py`，144×96 的立绘有 9473 个像素发生变化。所以
> **概念稿一旦定稿就不要再压缩**，压缩要在第一次导入素材之前做完。
> `concept_counter_*.png` 这两张早期柜台稿因此保留未压缩的原始文件。
提示词固定包含这几段，缺一不可：

1. **风格锚定**：`cozy hand-painted pixel art, same art direction as Stardew Valley:
   rich color ramps, dark brown outlines, soft warm highlights, no blur`，
   并把已确认的概念稿作为 `reference_image_paths` 传入，保证批次之间不跑偏。
2. **调色板**：显式给出暖棕 `#765039 #b18459 #49301f`、青蓝 `#527b84 #294f58`、
   屏幕光 `#3a8fc5`、米白 `#ffe9c9`、描边 `#2a1d12`。
3. **视角**：设施与家具用 `3/4 top-down oblique, camera looking down about 45 degrees`；
   **联排机位必须用 `steep overhead view, about 70 degrees`，并明确要求
   `the artwork must be wide and shallow — total height about 40% of total width`**。
   45 度画出来的联排桌深 144px，四排并列会互相吃掉椅子。
4. **抠图底**：`background is a completely flat uniform pure magenta #FF00FF chroma key
   field, no gradient, no texture, no shadow cast onto the background`。
   一定要写 `no shadow cast onto the background`，否则生图会把落地阴影画在洋红上，
   混出暗洋红，抠图后残留一圈紫边。
5. **拼版**：多个物件排在一张图上时，要求
   `each object fully isolated with a very wide empty magenta gap between them`，
   脚本靠空白带自动切分，间隔不够会切不开。

## 四、像素化处理

`pixelize_object.py` 提供公共步骤，`import_stage_concepts.py` 批量调度。

1. **抠洋红**。按色相判定而非亮度：`spill = min(R, B) - G`，`spill > 100` 即背景。
   实测概念稿里背景像素的 spill 全在 200 以上，物件（包括粉发、紫夹克）全在 40 以下，
   中间几乎没有过渡值，所以阈值放在 100 一刀两断很安全。抠完再向外膨胀 2px，
   啃掉边缘抗锯齿混进来的洋红。
2. **切分拼版**。对 alpha 做行列投影，忽略短于 12px 的空隙，行优先返回。
   50 人拼版里衣摆间最窄空隙只有 12px；角色内部不会形成贯穿全高的空列，
   因而这个阈值既能分开相邻人物，也不会把人物肢体误切。
3. **按目标比例补透明边**，避免物件被拉伸。
4. **预乘 alpha 的面积平均降采样**。必须预乘，否则透明区的黑会顺着 box 平均渗进
   物件边缘，留一圈脏边。降采样后 alpha 按 0.5 二值化，像素风不保留半透明。
5. **统一调色板**。`world` 使用 64 色，`npc` 和 `pc_portrait` 各使用 96 色：
   家具建筑要共享同一套材质色阶；50 名角色要保住年龄、发色、肤色和职业服装差异；
   六代机位详情需要独立保住红光、RGB、冰蓝、白色与电光青，不被大面积木棕吞掉。
   采样时每个素材按固定配额均匀重采样——直接堆全部像素的话，联排（36864 px）会盖过
   绿植（2304 px），调色板被木棕吃满，绿色和商品色全掉。

## 五、常用命令

```bash
# 批量导入全部概念稿（改了 SHEETS 或概念稿后跑）
python3 godot/tools/import_stage_concepts.py

# 只看切分结果与宽高比，用来定目标尺寸
python3 godot/tools/import_stage_concepts.py --measure

# 单个物件试做，不写进 assets
python3 godot/tools/pixelize_object.py <概念稿> stations/pc_test --size 64x68 --dry-run

# 重生成 tile 与反馈图标
python3 godot/tools/gen_stage_tiles.py

# 校验 50 人数据与全部 sprite，生成阵容预览，并把人设注入布局草图
python3 tools/validate_customer_roster.py

# 校验六代机位数据与双尺寸素材，生成对照图并注入布局草图
python3 tools/validate_pc_configs.py

# 导入 Godot 并出验证截图
godot --headless --path godot --import
godot --path godot --script res://tools/screenshot.gd
```

截图脚本需要真实渲染器，`--headless` 下 dummy 渲染器返回空纹理，存不出图。

## 六、加新素材的步骤

1. 按第三节的约定生成概念稿，存进 `docs/ui/concept/`（记得索引化压缩）。
2. 在 `import_stage_concepts.py` 的 `SHEETS` 里加一条：概念稿名、调色板组、
   目标素材名与尺寸。拼版的话按阅读顺序列出全部物件。
3. 跑 `--measure` 看切分数量对不对、原始宽高比是多少，据此把目标尺寸调到
   接近原比例，避免补太多透明边。
4. 正式跑一次，检查 `docs/ui/preview/stage_assets@4x.png`。
5. 在 `stage_controller.gd` 里摆放，然后出截图验证。

## 七、50 人顾客批次

- 固定角色库：`godot/data/customers.json`，由 `tools/generate_customer_roster.py`
  以固定种子生成并固化，名字与 sprite 编号永远一一对应。
- 分布：30 男、20 女；18–24、25–34、35–44、45–54、55–60 五个年龄段各 10 人。
- 概念稿：`customers_01_05.png` 至 `customers_46_50.png`，共十张，每张严格按
  从左到右 3 男 2 女排列。
- 输出：`customer_01_idle.png` 至 `customer_50_idle.png`，统一 32×72 透明画布；
  身高差直接画在画布内部，不在 Godot 运行时缩放。
- 阵容预览：`docs/ui/preview/customers_roster@4x.png`。
- 布局草图 `布局草图-像素风.html` 末尾也有一屏 NPC 阵容，立绘直接引用
  `assets/world/npc/`，人设由校验脚本注入页内 `roster-data` 数据块。
  内联而不是 `fetch` 是为了让草图双击用 `file://` 打开就能看，不必起本地服务。
  改了 `customers.json` 或重导素材后，跑一次校验脚本再刷新页面即可。

## 八、六代机位批次

- 配置库：`godot/data/pc_configs.json`，以 x60 档贯穿 GTX 9、10 和 RTX 20、30、40、50 系。
- 场景概念稿：`pc_station_gen_*.png`，陡俯视、完整单座套装，导出为 64×68。
- 详情概念稿：`pc_portrait_gen_*.png`，45 度近景，导出为 144×96。
- 两种构图分别生图，详情稿以同代场景稿为参考图，保证显示器、主机、桌椅配色一致。
- 场景每台机位独立持有 `config_id`；初始 40 台全为 `gen_09`，其余五代只预置，
  后续升级时可逐台替换，不依赖整排底图。
- 对照预览：`docs/ui/preview/pc_generations@2x.png`；校验脚本同时把六代摘要
  注入布局草图的 `pc-config-data` 数据块。
